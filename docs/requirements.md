# Agent 收件箱 — 需求文档

版本：v0.1（MVP）
日期：2026-11-04
状态：评审中

## 1. 背景与问题

同时开多个本地 AI Agent（DSH 会话、Codex 线程、Claude Code 会话）时，用户频繁在窗口之间切换。真正的问题不是“找不到”，而是：

- 某个 Agent 已经跑完，但用户没有注意到；
- 用户不记得某条对话是否看过、是否还需要跟进；
- 会话分散在不同应用和不同入口，缺少一个统一的“收件箱”。

现有的多 Agent 工具大多是“由它来启动 Agent”（Claude Squad、Clauditor、CodeHerd），或者只是“事后浏览历史”（Claude Code History Viewer、opcode）。用户需要的是一个**只读、旁路**的监控面板：不接管 Agent，不改变现有工作流，只负责发现、汇总和提醒。

## 2. 目标

做一个 Windows 桌面小工具，托盘常驻，提供统一列表：

1. 自动发现本机主流 Agent 的会话，并登记到收件箱；
2. 展示每条会话的标题、来源、项目目录、最近活动和完成状态；
3. 当会话的一轮对话完成时，把它标记为“待看”并提醒；
4. 每条记录前有复选框，点击后标记该条为“已完成”；
5. 点击记录可以把对应的 Agent 应用窗口切到前台；
6. 支持清理已完成记录，清理后不重复出现，除非该会话又有新的完成。

### 非目标（MVP 不做）

- 不启动、不托管、不修改任何 Agent 进程；
- 不读取或上传对话正文到网络；
- 不在应用内继续聊天；
- 不做跨设备同步；
- 不承诺精确到“某个浏览器标签页／某个终端面板”的跳转，只承诺把宿主应用窗口切到前台；
- 不覆盖所有 Agent，先支持 DSH、Codex、Claude Code，保留扩展接口。

## 3. 用户与典型场景

**用户**：需要同时推进多个任务的开发者，桌面上长期开着 DSH Web GUI、Codex Desktop、Claude Code（VS Code 扩展或终端）。

**场景 A：扫一眼谁跑完了**
用户正在写代码，收件箱小窗常驻屏幕角落。某个 Codex 线程完成，列表顶部出现“待看”，托盘弹出通知。

**场景 B：批量清理**
用户处理完几条会话，逐条勾选“已完成”，点击“清理已完成”，列表只剩进行中和待看的。

**场景 C：回到某个 Agent**
用户点击一条 DSH 记录，应用把 Chrome 窗口切到前台，并在应用内提示“DSH 在浏览器标签页中”，用户按标题在侧边栏定位。

**场景 D：重启电脑后继续**
收件箱状态持久化：哪些看过、哪些完成、哪些清理过，重启后仍然保留；已清理的旧会话不会因为重新扫描又冒出来。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 会话（Session） | 一个 Agent 的一段连续对话，有稳定 ID、标题、工作目录 |
| 轮次（Turn） | 用户发一次消息到 Agent 完成本轮回答，为一个轮次 |
| 完成（Completed） | 当前没有正在执行的轮次，且至少完成过一轮 |
| 待看（Unread） | 新完成、用户还没点开过的记录 |
| 已完成（Done） | 用户勾选了复选框的记录 |
| 清理（Clear） | 从收件箱移除记录，写入隐藏墓碑；同一会话出现新的完成时可重新出现 |

## 5. 支持的 Agent 来源

| 来源 | 数据位置 | 标题来源 | 完成判定 |
|---|---|---|---|
| DSH | `~/.dsh/storages/session_projcache/sessions/*.json`；`~/.dsh/storages/workspace.json` | 投影缓存 `rows.title.val`，回退 `titleInput.first.text` | `sessionStats.openStep == null` 且 `pendingCalls` 为空，且 `lastTurn` 存在 |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl`；`~/.codex/session_index.jsonl` | `session_index.jsonl` 的 `thread_name`，回退首条用户消息 | 最后一条轮次标记为 `task_complete`；`task_started` 为进行中；`turn_aborted` 为已中断 |
| Claude Code | `~/.claude/projects/<project>/<sessionId>.jsonl` | 首条用户消息（截断），回退最后一条 `last-prompt` | 最后标记为 `last-prompt` / `cost-state` / `end_turn` 视为完成；`tool_use` 或工具结果之后视为进行中 |

补充规则：

- 所有来源只读，不写回 Agent 数据；
- DSH 跳过 `workspace.json` 中已归档的会话、空白会话；
- Codex 跳过 `archived_sessions`；
- Claude Code 跳过 `isSidechain` 的子代理消息用于状态判定；
- 来源路径允许在设置中覆盖，默认取用户目录；
- 单个来源解析失败不影响其他来源，错误在“数据源”页可见。

## 6. 功能需求

### FR-1 发现与登记（P0）

- 启动时并发扫描所有启用来源；
- 自动登记满足以下任一条件的会话：
  - 最近 `lookbackDays` 天（默认 3 天）内有活动；
  - 当前正在进行中；
  - 已在收件箱中（即使变旧也保留）；
- 空白会话（无标题、无用户消息）不登记；
- 支持手动“重新扫描”和“登记最近 N 天”；
- 设置中显示每个来源的可用状态、路径和发现数量。

### FR-2 列表（P0）

每条记录展示：

- 复选框；
- 来源徽标（DSH / Codex / Claude）；
- 会话标题（最多两行，超出省略）；
- 项目目录（只显示最后两级，完整路径放在悬浮提示）；
- 相对时间（“2 分钟前”）；
- 状态：进行中 / 待看 / 已完成 / 已中断；
- 新完成时有高亮点或“NEW”标记。

排序：待看（按完成时间倒序）→ 进行中（按活动时间倒序）→ 已完成（按完成时间倒序）。
筛选：全部 / 待看 / 进行中 / 已完成。
搜索：按标题、目录过滤（P1）。

### FR-3 完成检测与提醒（P0）

- 扫描周期默认 4 秒，文件变化时防抖触发；
- 应用启动后的第一次扫描不把更早的历史全部标成“新完成”；最近 2 小时内完成的会话标为“待看”但不弹通知；
- 同一会话的 `completionKey` 变化且新状态为完成时：
  - 记录变为“待看”，`seen=false`，`done=false`；
  - 若窗口不可见或未聚焦，托盘气泡通知“对话完成：<标题>”；
  - 若记录此前被清理（hidden），自动重新出现；
- 通知可在设置中关闭。

### FR-4 标记完成（P0）

- 复选框点击切换 `done`；
- 勾选后立即写入本地状态，记录降到“已完成”分组；
- 取消勾选可恢复；
- 勾选不影响会话本身，也不关闭 Agent。

### FR-5 点击跳转（P0）

- 点击记录主体（复选框以外区域）：
  - 清除“未读”标记（`seen=true`）；
  - 把记录所属应用的窗口切到前台；
  - 应用内 toast 显示结果（成功 / 未找到窗口）；
- 窗口匹配顺序：
  - DSH：标题含会话标题或 “DeepSeek Harness” 的浏览器窗口 → 任一浏览器窗口；
  - Codex：ChatGPT / Codex 桌面窗口；
  - Claude Code：标题含项目目录名或 “Claude” 的 VS Code / Windows Terminal 窗口 → 任一 VS Code / 终端窗口；
- 找不到窗口时只提示，不报错，不启动新进程；
- 右键菜单提供“复制标题”“复制会话 ID”“复制项目路径”。

### FR-6 清理（P0）

- “清理已完成”：把所有 `done` 记录设为 hidden；
- “全部清理”：二次确认后把所有当前记录设为 hidden；
- 清理只影响收件箱，不删除 Agent 数据；
- 被清理会话再次完成时重新出现；
- 清理后保留墓碑，重启不复活。

### FR-7 托盘与窗口（P0）

- 系统托盘常驻；关闭窗口 = 隐藏到托盘，不退出；
- 托盘菜单：显示/隐藏、置顶开关、立即刷新、退出；
- 窗口默认 420×640，可调整大小，位置和大小记忆；
- 支持“始终置顶”开关（标题栏图钉）；
- 单实例：重复启动只唤起已有窗口；
- 可选开机自启（写入 HKCU Run）。

### FR-8 设置（P1）

- 来源开关与路径覆盖；
- 扫描间隔、登记回看天数；
- 完成通知开关；
- 置顶、开机自启；
- 清空收件箱数据（二次确认）。

### FR-9 可观测性（P1）

- “数据源”页展示每个来源最近一次扫描时间、耗时、发现数、错误；
- 日志写入 `%APPDATA%\AgentInbox\logs\app.log`，按天滚动，保留 7 天；
- 诊断模式：`AgentInbox.exe --diagnose` 输出发现结果 JSON 后退出，便于排查。

## 7. 状态模型

```
                ┌──────────────┐
   新完成 ─────▶│   待看 Unread │──点击记录──▶ 已看过 Seen
                └──────┬───────┘                  │
                       │ 勾选                     │ 勾选
                       ▼                          ▼
                ┌──────────────┐           ┌──────────────┐
                │  已完成 Done  │◀──────────│  已完成 Done  │
                └──────┬───────┘           └──────────────┘
                       │ 清理
                       ▼
                ┌──────────────┐
                │  隐藏 Hidden  │──同一会话新完成──▶ 待看
                └──────────────┘
```

持久化字段（每条记录）：

```json
{
  "key": "codex:00000000-0000-0000-0000-000000000000",
  "source": "codex",
  "sessionId": "00000000-0000-0000-0000-000000000000",
  "title": "整理发布说明",
  "cwd": "D:\\Workspace\\sample-app",
  "addedAt": "2026-01-15T08:00:00Z",
  "lastActivityAt": "2026-01-15T08:30:00Z",
  "completionKey": "turn:demo-turn",
  "completedAt": "2026-01-15T08:30:00Z",
  "seen": false,
  "done": false,
  "doneAt": null,
  "hidden": false,
  "hiddenAt": null
}
```

## 8. 非功能需求

- **隐私**：所有数据留在本机；不联网；不读取对话正文用于展示（只读取标题/时间/状态所需字段）。
- **性能**：冷启动 3 秒内出首屏（70+ 会话）；扫描增量进行，不阻塞 UI；常驻内存目标 < 450 MB（WPF + WebView2，实测主进程约 330 MB 私有内存）。
- **健壮性**：Agent 正在写文件时容忍半行/截断；解析失败跳过该条并记录日志；不因单个坏文件崩溃。
- **兼容性**：Windows 10/11 x64；WebView2 Runtime（Win11 自带，Win10 缺失时提示安装）。
- **可维护性**：来源适配器接口独立，新增来源不改核心状态机。

## 9. 验收标准

1. 机器上存在 DSH / Codex / Claude Code 会话时，启动后 3 秒内列表出现记录，标题与各自应用内一致（允许截断）。
2. 在 Codex 里跑完一轮，4 秒内列表出现“待看”，托盘出现通知。
3. 勾选一条记录，重启应用后仍为已完成。
4. 点击“清理已完成”，记录消失；重启后不出现；该会话再完成一轮后重新出现。
5. 点击记录，对应应用窗口被切到前台；应用不可用时给出明确提示。
6. 关闭窗口后应用仍在托盘；托盘菜单可恢复窗口、切换置顶、退出。
7. 关闭网络后全部功能可用。
8. `--diagnose` 能输出三类来源的发现结果，单个来源损坏不影响其他来源。

## 10. 风险与限制

| 风险 | 影响 | 应对 |
|---|---|---|
| DSH 投影缓存不是公开 API，字段可能变 | DSH 来源失效 | 适配器容错；缺失字段时降级为“未知”；后续可改用会话日志 |
| Codex / Claude Code 日志格式随版本变化 | 状态误判 | 只依赖稳定的轮次边界标记；解析失败保留“未知”状态；日志可诊断 |
| 浏览器只有一个窗口、多个标签页 | DSH 点击只能切窗口，不能切标签 | 需求已确认接受；标题复制辅助定位；后续可做浏览器插件增强 |
| 终端里跑 Claude Code 时窗口标题不含会话信息 | 可能切错终端 | 优先匹配项目目录名；退化为“最近使用的终端” |
| 文件名/路径含中文或超长 | 解析失败 | 全链路 UTF-8；异常隔离 |
